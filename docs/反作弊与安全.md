# 反作弊与安全

这个插件最核心的设计目标：**AI 能听话、能干活，但不能碰任何能破坏平衡的东西。**

三道锁，缺一不可。

## 锁一：动作白名单

LSE 给模拟玩家（`Player` 的 `simulate*` 系列）提供了大量能力，其中一部分等于管理员权限。插件只允许 5 个动作：

```js
const ALLOWED_SIM = [
  'simulateMoveTo',    // 走位
  'simulateLookAt',    // 转头
  'simulateStopMoving',// 停下
  'simulateJump',      // 跳
  'simulateSneak'      // 潜行
];
```

所有调用都经过同一个闸门：

```js
function safeSim(sp, method, args) {
  if (!ALLOWED_SIM.includes(method)) {
    audit('[GUARD] 拒绝动作 ' + method);
    return false;
  }
  try {
    const r = sp[method].apply(sp, args);
    if (r !== true) audit('[GUARD] 动作执行失败 ' + method + ': ' + r);
    return r === true;
  } catch (e) {
    audit('[GUARD] 动作异常 ' + method + ': ' + e);
    return false;
  }
}
```

白名单之外的 `simulate*`（比如给物品、改模式、传送、飞行）根本不会出现在代码里，
就算模型在回答里「要求」它这么做，也没有任何代码路径能执行。

## 锁二：模型输出只读

模型返回的字符串只经过一条出口：

```js
mc.broadcast(reply);   // 只是聊天栏文字
```

它**不能**拼成命令，也**不会**进 `mc.runcmd`。系统提示词里另外明确写了：

> 你没有管理员权限：不能发物品、不能改游戏模式、不能开创造、不能传送、不能改血量。

实测问「给我 64 个钻石块」，回答是：

> 我要有那本事早给自己囤一箱了，可惜只会动嘴。找服主去，别指望我变钻石。

问「小鲸能刷物品吗」：

> 不能。小鲸没有管理员权限，不会发物品、改模式或开创造，只会走动和聊天。

## 锁三：审计 + 自检

每次召唤、移动、改名、扣费、被拦截的动作都写进 `logs/audit.log`：

```
[SPAWN] 为 tester01 召唤助手 小蓝 @ 394,128,1942
[MOVE] 过来 -> 394,128,1942
[MOVE_END] 过来 now=394,129,1942
[RENAME] tester01 把助手 小蓝 改成 小绿
[PAY] tester01 购买 30 分钟，扣 600 金币
[GUARD] 拒绝动作 simulateGive
```

`aiadmin selftest` 会扫自己的源码，确认没有危险调用：

```js
const needles = ['gi' + 've', 'setGame' + 'Mode', 'addI' + 'tem', 'setHe' + 'alth'];
```

（字符串故意拼开，避免扫描时匹配到自己。）

同时用桩玩家跑一次扣费：余额 1000 → 买 30 分钟扣 600 → 剩 400；把余额设成 599 再买，必须被拒。

## 权限边界

| 能 | 不能 |
|---|---|
| 走动、转头、跳、潜行 | 给物品 / 刷方块 |
| 聊天、回答玩法问题 | 改游戏模式 / 开创造 |
| 被玩家指挥走位 | 传送玩家 / 改血量 |
| 播报文字（管理员可用 `公告`） | 执行任意命令 |

## 其他安全建议

- `llm.key` 不要提交到版本库（`.gitignore` 已排除），也不要贴到群里
- 用临时/限额的 API key，模型网关如果支持，限制每分钟调用次数
- 如果模型是公网 API，注意玩家聊天内容会发到该服务商；介意的话用本地模型
- `logs/audit.log` 建议保留，出问题时是唯一可信的时间线
